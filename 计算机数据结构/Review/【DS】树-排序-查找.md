## 一、树（Tree）

### 1.1 二叉树核心性质（必背）

| 性质 | 内容 |
|------|------|
| **性质1** | 第 $i$ 层最多有 $2^{i-1}$ 个结点（$i \geq 1$） |
| **性质2** | 深度为 $k$ 的二叉树最多有 $2^k - 1$ 个结点 |
| **性质3** | 叶子结点数 $n_0$ = 度为2的结点数 $n_2$ + 1，即 $n_0 = n_2 + 1$ |
| **性质4** | 具有 $n$ 个结点的完全二叉树深度为 $\lfloor \log_2 n 
floor + 1$ |
| **性质5** | 完全二叉树中，结点 $i$ 的父节点为 $\lfloor i/2 
floor$，左孩子 $2i$，右孩子 $2i+1$ |

**完全二叉树 vs 满二叉树**：满二叉树是每层都满的完全二叉树；完全二叉树最后一层可以不满，但结点必须集中在左侧。

### 1.2 二叉树遍历（核心中的核心）

```
        1
       / \
      2   3
     / \   /
    4   5 6
```

- **前序**：根左右 → `1 2 4 5 3 6`
- **中序**：左根右 → `4 2 5 1 6 3`
- **后序**：左右根 → `4 5 2 6 3 1`
- **层序**：逐层 → `1 2 3 4 5 6`

**重要结论**：
- 已知**前序+中序** 或 **后序+中序** 可唯一确定二叉树
- 已知**前序+后序** **不能**唯一确定二叉树（除非是完全二叉树）
- **中序遍历**下，二叉搜索树得到有序序列

### 1.3 线索二叉树

将空指针域利用起来，指向遍历前驱/后继：
- `ltag=0`：lchild指向左孩子；`ltag=1`：lchild指向前驱
- `rtag=0`：rchild指向右孩子；`rtag=1`：rchild指向后继

**中序线索化**后，找前驱/后继无需递归，时间 $O(1)$，适合频繁遍历场景。

### 1.4 二叉搜索树（BST）

**性质**：左子树 < 根 < 右子树，中序遍历有序。

**查找**：从根开始，目标小往左，大往右，平均 $O(\log n)$，最坏 $O(n)$（退化成链表）。

**插入**：从根找到合适位置，作为叶子插入。

**删除**（三种情况）：
1. **叶子结点**：直接删除
2. **只有一棵子树**：用子树顶替
3. **有两棵子树**：用**中序直接后继**（右子树最小值）或**中序直接前驱**（左子树最大值）替换，再删除那个结点

### 1.5 平衡二叉树（AVL）

**平衡因子**：左子树高 - 右子树高，取值只能是 -1, 0, 1。

**失衡调整**（四种旋转）：

| 插入位置 | 失衡类型 | 旋转方式 |
|---------|---------|---------|
| 左子树的左子树 | LL | 右旋 |
| 左子树的右子树 | LR | 先左旋再右旋 |
| 右子树的右子树 | RR | 左旋 |
| 右子树的左子树 | RL | 先右旋再左旋 |

**记忆口诀**：LL右旋，RR左旋，LR先左后右，RL先右后左。

**最小不平衡子树**：从插入点向上找第一个平衡因子绝对值 > 1 的结点，以它为根旋转。

### 1.6 B树与B+树（了解概念即可）

**B树（m阶）**：
- 每个结点最多 $m$ 棵子树，最多 $m-1$ 个关键字
- 根结点最少2棵子树，非根非叶最少 $\lceil m/2 
ceil$ 棵子树
- 所有叶子在同一层
- 关键字按升序排列，左子树 < 关键字 < 右子树

**B+树**：
- 非叶子结点只作索引，关键字在叶子结点冗余一份
- 叶子结点用指针链接，支持顺序查找
- **MySQL索引**常用B+树

## 二、排序（Sorting）

### 2.1 总览表（必背）

| 排序方法 | 平均时间 | 最好时间 | 最坏时间 | 空间复杂度 | 稳定性 | 每次确定位置？ |
|---------|---------|---------|---------|-----------|--------|-------------|
| 直接插入 | $O(n^2)$ | $O(n)$ | $O(n^2)$ | $O(1)$ | ✅ 稳定 | ❌ 否 |
| 希尔排序 | $O(n^{1.3})$ | — | $O(n^2)$ | $O(1)$ | ❌ 不稳定 | ❌ 否 |
| 冒泡排序 | $O(n^2)$ | $O(n)$ | $O(n^2)$ | $O(1)$ | ✅ 稳定 | ✅ **每次确定一个（最大/最小到末尾）** |
| 快速排序 | $O(n\log n)$ | $O(n\log n)$ | $O(n^2)$ | $O(\log n)$ | ❌ 不稳定 | ✅ **每次确定枢轴到最终位置** |
| 简单选择 | $O(n^2)$ | $O(n^2)$ | $O(n^2)$ | $O(1)$ | ❌ 不稳定 | ✅ **每次确定一个（最小到开头）** |
| **堆排序** | $O(n\log n)$ | $O(n\log n)$ | $O(n\log n)$ | $O(1)$ | ❌ 不稳定 | ✅ **每次确定一个（最大到末尾）** |
| 归并排序 | $O(n\log n)$ | $O(n\log n)$ | $O(n\log n)$ | $O(n)$ | ✅ 稳定 | ❌ 否（需完整归并） |
| 基数排序 | $O(d(n+r))$ | $O(d(n+r))$ | $O(d(n+r))$ | $O(r)$ | ✅ 稳定 | ❌ 否 |

> **考研常考**：排序过程模拟、稳定性判断、比较次数分析、是否每次确定位置。

### 2.2 各排序核心逻辑与"是否每次确定位置"

#### ① 冒泡排序

**核心**：相邻两两比较，逆序则交换，每轮将最大元素"冒"到末尾。

```
第1轮：最大元素到第 n 位
第2轮：次大元素到第 n-1 位
...
```

**是否确定位置**：✅ **是**。每一轮结束，当前未排序部分的最大元素一定在正确的最终位置（末尾）。

#### ② 快速排序

**核心**：选枢轴，一趟排序后枢轴左边都小，右边都大。

```
一趟快排后：枢轴位于最终正确位置
左边继续快排，右边继续快排
```

**是否确定位置**：✅ **是**。每一趟排序后，**枢轴元素**一定在最终正确位置。其他元素位置不确定。

#### ③ 简单选择排序

**核心**：每轮在未排序部分找最小元素，放到已排序末尾。

```
第1轮：最小元素放到第1位
第2轮：次小元素放到第2位
...
```

**是否确定位置**：✅ **是**。每一轮结束，当前最小元素一定在正确的最终位置（开头）。

#### ④ 堆排序（重点详解）

**是否确定位置**：✅ **是**。每轮输出堆顶（最大/最小）放到末尾，该元素位置确定。

### 2.3 堆排序详解（考研高频）

#### 2.3.1 堆的定义

**大根堆**：完全二叉树，每个结点 $\geq$ 其左右孩子（堆顶是最大值）。
**小根堆**：完全二叉树，每个结点 $\leq$ 其左右孩子（堆顶是最小值）。

> 堆一定是完全二叉树，可用数组存储：结点 $i$ 的左孩子 $2i$，右孩子 $2i+1$，父结点 $\lfloor i/2 
floor$。

#### 2.3.2 建堆（Heapify）—— 核心操作

**方法**：从最后一个非叶子结点开始，自底向上执行"向下调整"。

```
数组: [49, 38, 65, 97, 76, 13, 27, 49]

完全二叉树形式：
        49(1)
       /    \
    38(2)   65(3)
   /   \    /  \
 97(4) 76(5)13(6)27(7)
 /
49(8)

最后一个非叶子结点 = n/2 = 4（值为97）
从4开始往前调整：4→3→2→1
```

**向下调整（大根堆）**：
1. 比较当前结点与其左右孩子
2. 若孩子更大，与最大的孩子交换
3. 交换后可能破坏子树堆性质，继续向下调整
4. 直到当前结点 $\geq$ 两个孩子，或到达叶子

**建堆时间复杂度**：$O(n)$（不是 $O(n\log n)$！因为大部分结点调整次数很少）

#### 2.3.3 堆排序过程

```
初始数组：[49, 38, 65, 97, 76, 13, 27, 49]

Step 1: 建大根堆 → [97, 76, 65, 49, 38, 13, 27, 49]
Step 2: 交换堆顶(97)与末尾(49) → [49, 76, 65, 49, 38, 13, 27, 97]
         对前7个元素调整堆 → [76, 49, 65, 49, 38, 13, 27, 97]
Step 3: 交换堆顶(76)与第7位(27) → [27, 49, 65, 49, 38, 13, 76, 97]
         对前6个元素调整堆 → [65, 49, 27, 49, 38, 13, 76, 97]
...继续直到排序完成
```

**每轮确定位置**：每轮将当前最大值放到数组末尾，该元素位置确定。

#### 2.3.4 堆的插入（向上调整）

**场景**：向堆中插入一个新元素。

**步骤**：
1. 将新元素放在堆的末尾（数组最后）
2. 与其父结点比较，若比父结点大（大根堆），则交换
3. 继续向上比较，直到满足堆性质或到达根

```
大根堆：[97, 76, 65, 49, 38, 13, 27]
插入 80：
  先放末尾：[97, 76, 65, 49, 38, 13, 27, 80]
  80与父38比较，80>38，交换
  [97, 76, 65, 49, 80, 13, 27, 38]
  80与父76比较，80>76，交换
  [97, 80, 65, 49, 76, 13, 27, 38]
  80与父97比较，80<97，停止
```

**时间复杂度**：$O(\log n)$（最多从叶子走到根）

#### 2.3.5 堆的删除（向下调整）

**场景**：删除堆顶元素（通常用于取最大值/最小值）。

**步骤**：
1. 用堆的最后一个元素替换堆顶
2. 堆大小减1
3. 从堆顶开始向下调整

```
大根堆：[97, 80, 65, 49, 76, 13, 27, 38]
删除堆顶97：
  用末尾38替换堆顶：[38, 80, 65, 49, 76, 13, 27]
  38与左右孩子(80,65)比较，最大是80，交换
  [80, 38, 65, 49, 76, 13, 27]
  38与左右孩子(49,76)比较，最大是76，交换
  [80, 76, 65, 49, 38, 13, 27]
  38与左右孩子(无)比较，停止
```

**时间复杂度**：$O(\log n)$

> **考研注意**：删除任意位置元素也是同样逻辑（用末尾替换，向上或向下调整），但通常只考删除堆顶。

### 2.4 希尔排序（缩小增量排序）

**核心**：将序列按增量 $d$ 分组，组内直接插入排序，逐步减小 $d$ 直到1。

```
初始：49 38 65 97 76 13 27 49 55 04

d=5: 分组 (49,13), (38,27), (65,49), (97,55), (76,04)
     组内排序后：13 27 49 55 04 49 38 65 97 76

d=2: 分组 (13,49,04,38,97), (27,55,49,65,76)
     组内排序后：04 13 38 49 49 55 65 76 27 97 → 04 13 27 38 49 49 55 65 76 97

d=1: 直接插入排序（此时基本有序，效率高）
```

**增量序列**：常用 Shell 序列 $d = n/2, n/4, ... , 1$；或 Knuth 序列 $d = 3d+1$。

**是否确定位置**：❌ **否**。希尔排序是全局逐步有序，没有哪一轮能确定某个元素的最终位置。

### 2.5 归并排序

**核心**：分治法，将序列分成两半，分别排序，再合并。

```
[49, 38, 65, 97, 76, 13, 27]

分解：[49,38,65,97]  [76,13,27]
      [49,38] [65,97]  [76,13] [27]
      [49] [38] [65] [97] [76] [13] [27]

合并：[38,49] [65,97]  [13,76] [27]
      [38,49,65,97]  [13,27,76]
      [13,27,38,49,65,76,97]
```

**是否确定位置**：❌ **否**。只有整个归并过程完成后，所有元素位置才确定。中间过程只是局部有序。

## 三、查找（Search）

### 3.1 顺序查找与折半查找

#### 顺序查找
- 逐个比较，ASL（平均查找长度）成功：$(n+1)/2$，失败：$n+1$
- 适用：顺序表、链表
- 可设置**哨兵**：将待查值放在0号位置，从后往前找，减少越界判断

#### 折半查找（二分查找）
- 要求：**有序的顺序表**（数组）
- 过程：low=1, high=n，mid=(low+high)/2，比较后缩小范围
- ASL 成功：$pprox \log_2(n+1) - 1$，失败：$pprox \log_2(n+1)$
- **判定树**：折半查找的过程可用二叉判定树表示，树高 $\lceil \log_2(n+1) 
ceil$

> **注意**：折半查找**不适合链表**（无法随机访问），也不适合频繁插入删除的场景。

### 3.2 二叉搜索树查找
- 见"树一章"，平均 $O(\log n)$，最坏 $O(n)$

### 3.3 哈希表（散列表）

**核心思想**：通过哈希函数 $H(key)$ 直接计算存储地址，实现 $O(1)$ 查找。

**哈希函数构造**：
- 直接定址法：$H(key) = a \cdot key + b$
- 除留余数法：$H(key) = key \mod p$（$p$ 取不大于表长的最大素数）
- 数字分析法、平方取中法、折叠法

**冲突处理**：

| 方法 | 原理 | 特点 |
|------|------|------|
| **开放定址法** | 冲突后找下一个空地址 | 线性探测、二次探测、双散列 |
| **链地址法** | 冲突元素链成链表 | 不会产生聚集，ASL较低 |
| **再散列法** | 多个哈希函数，冲突换函数 | 计算量大 |
| **建立公共溢出区** | 冲突元素放溢出表 | 简单但效率低 |

**线性探测**：$H_i = (H(key) + d_i) \mod m$，$d_i = 1, 2, 3, ...$
- 优点：总能找到空位置
- 缺点：产生**聚集**（堆积）

**二次探测**：$d_i = 1^2, -1^2, 2^2, -2^2, ...$
- 减少聚集，但可能探测不到所有位置

**装填因子**：$lpha = n/m$（表中记录数/表长），ASL 依赖于 $lpha$：
- 线性探测成功：$ASL_{成功} pprox rac{1}{2}(1 + rac{1}{1-lpha})$
- 链地址法成功：$ASL_{成功} pprox 1 + rac{lpha}{2}$

### 3.4 并查集（Disjoint Set Union, DSU）

> 并查集是考研新增重点，常用于判断连通性、最小生成树（Kruskal算法）。

#### 3.4.1 基本概念

并查集维护若干个**不相交的集合**，支持两种操作：
- **Find(x)**：查找 $x$ 所在集合的代表（根）
- **Union(x, y)**：合并 $x$ 和 $y$ 所在的集合

#### 3.4.2 存储结构

用**数组**实现（森林的双亲表示法）：
- `parent[i]`：结点 $i$ 的父结点
- `parent[i] = -1` 或 `parent[i] = i` 表示 $i$ 是根结点

```
集合1：{0, 1, 2}    集合2：{3, 4}
    0                3
   / \               |
  1   2              4

parent数组：[-1, 0, 0, -1, 3]
```

#### 3.4.3 基本操作

**Find（查找）**：
```
Find(x):
    while parent[x] >= 0:    // 或 parent[x] != x
        x = parent[x]
    return x
```

**Union（合并）**：
```
Union(x, y):
    rootX = Find(x)
    rootY = Find(y)
    if rootX != rootY:
        parent[rootX] = rootY   // 将一棵树的根挂到另一棵树下
```

#### 3.4.4 优化一：路径压缩（Path Compression）

**问题**：树可能退化成链表，Find 最坏 $O(n)$。

**优化**：查找时，将路径上所有结点直接指向根，扁平化树。

```
Find(x):
    if parent[x] != x:
        parent[x] = Find(parent[x])   // 递归压缩路径
    return parent[x]
```

**效果**：经过路径压缩后，树高度接近1，后续查找几乎 $O(1)$。

#### 3.4.5 优化二：按秩合并（Union by Rank/Size）

**问题**：随意合并可能导致树变高。

**优化**：将矮树合并到高树下（或小结点合并到大树下）。

```
// 用 parent[root] 存储负数表示树的大小（或高度）
Union(x, y):
    rootX = Find(x), rootY = Find(y)
    if rootX == rootY: return

    // 按大小合并：小树挂到大树下
    if parent[rootX] > parent[rootY]:   // 负数比较，绝对值小的树更小
        swap(rootX, rootY)
    parent[rootX] += parent[rootY]       // 更新大小
    parent[rootY] = rootX
```

#### 3.4.6 时间复杂度

- **只路径压缩** 或 **只按秩合并**：单次操作近似 $O(\log n)$
- **两者都用**：单次操作近似 $O(lpha(n))$，其中 $lpha$ 是阿克曼函数的反函数，**小于5**，可视为常数！

#### 3.4.7 应用场景

| 场景 | 用法 |
|------|------|
| **连通分量** | 初始每个点独立集合，边连接两点则Union，最后统计根结点数量 |
| **Kruskal最小生成树** | 按边权排序，若边两端点不在同一集合则加入，并Union |
| **等价类划分** | 将等价元素合并到同一集合 |
| **最近公共祖先（LCA）** | 离线算法配合并查集 |

## 四、考研常考题型与技巧

### 4.1 排序过程模拟（手撕代码）

考研常给一组数据，要求写出某排序的**每轮结果**。

**技巧**：
- 冒泡：每轮末尾多一个确定元素，前面可能仍有交换
- 快排：先确定枢轴位置，再递归左右（注意递归顺序不影响结果，但过程写法要规范）
- 堆排：先建堆，再每轮交换+调整，注意调整只影响从根到叶子的路径
- 希尔：按增量分组，组内排序，注意是**所有组同时处理**还是**一组一组处理**（通常理解为所有组同时处理）

### 4.2 稳定性判断技巧

**稳定排序**：相等元素相对位置不变。
- **插入类**（直接插入、希尔）+ **交换类中的冒泡** + **归并** + **基数** = 稳定
- **选择类**（简单选择、堆排）+ **交换类中的快排** = 不稳定

**记忆口诀**：
> "插冒归基稳，选堆快希不稳"

### 4.3 比较次数分析

- **直接插入**：最好 $n-1$（已有序），最坏 $n(n-1)/2$（逆序）
- **冒泡**：最好 $n-1$（已有序，加flag优化），最坏 $n(n-1)/2$
- **快排**：最好/平均 $O(n\log n)$，最坏 $O(n^2)$（已有序或逆序）
- **简单选择**：**无论好坏都是 $n(n-1)/2$**，因为每轮都要扫描全部未排序元素找最小值

### 4.4 堆排序建堆细节

**常考陷阱**：
- 建堆是**从最后一个非叶子结点开始**（$\lfloor n/2 
floor$），不是从根开始！
- 建堆时间 $O(n)$，不是 $O(n\log n)$
- 堆排序总时间 $O(n\log n)$，因为建堆 $O(n)$ + $n$ 次调整 $O(n\log n)$
- 堆排序**空间 $O(1)$**，是原地排序

### 5.2 并查集代码模板

```cpp
// 初始化
void Init(int parent[], int n) {
    for (int i = 0; i < n; i++) 
        parent[i] = -1;  // 负数表示根，绝对值表示集合大小
}

// 查找（带路径压缩）
int Find(int parent[], int x) {
    if (parent[x] < 0) return x;  // x是根
    return parent[x] = Find(parent, parent[x]);  // 路径压缩
}

// 合并（按大小合并）
void Union(int parent[], int x, int y) {
    int rootX = Find(parent, x);
    int rootY = Find(parent, y);
    if (rootX == rootY) return;

    // 小树合并到大树（parent存的是负数大小）
    if (parent[rootX] > parent[rootY])  // 例如 -2 > -5，说明rootX更小
        swap(rootX, rootY);

    parent[rootX] += parent[rootY];  // 更新大小
    parent[rootY] = rootX;            // rootY挂到rootX下
}
```
