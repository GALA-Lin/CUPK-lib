## Chapter 1: Introduction (导论)
第 1 章：导论

### Core Knowledge
核心知识

1.  **Definition of Software Engineering (SE)**: An engineering discipline covering all aspects of software production, ranging from specification to maintenance.
    软件工程（SE）的定义：涵盖软件生产所有方面的工程学科，从规范到维护。
2.  **Software Product Types**: Generic products (with specifications owned by developers) and Customized products (with specifications owned by customers).
    软件产品类型：通用产品（规范由开发者拥有）和定制产品（规范由客户拥有）。
3.  **Fundamental SE Activities**: Specification → Design & Development → Validation → Software Evolution/Maintenance.
    基本软件工程活动：规范 → 设计与开发 → 验证 → 软件进化/维护。
4.  **Software Failure Causes**: The **increasing complexity of the system** and the **failure to adopt software engineering methods.**
    软件故障原因：系统复杂性的增加以及未能采用软件工程方法。
5.  **General Issues Affecting Software**: Heterogeneity, business & social change, security & trust, and scale.
    影响软件的普遍问题：异构性、商业与社会变革、安全与信任，以及规模。
6.  **Professional Software Components**: Programs, associated documentation, libraries, and configuration data.
    专业软件组件：程序、相关文档、库和配置数据。
7.  **Professional Responsibilities**: Confidentiality, competence, intellectual property rights, and computer misuse.
    专业责任：保密性、能力、知识产权和计算机滥用。

### Key Exam Points
关键考试要点

*   Frequently - tested True/False questions: There are no universal SE methods; SE supports professional software development rather than individual programming.
    经过频繁测试的真/假题：没有通用的软件工程方法；软件工程支持专业软件开发而非个人编程。
*   Fill - in - the - blank focus: Software failure factors (software engineering), the general issue affecting software (scale), and professional responsibilities (competence).
    填空重点：软件故障因素（软件工程）、影响软件的普遍问题（规模）以及专业责任（能力）。
*   Case connection: The wilderness weather station belongs to data collection systems.
    案例关联：野外气象站属于数据收集系统。

## Chapter 2: Software Processes (软件过程)
第二章：软件过程（软件过程）

### Core Knowledge
核心知识

1.  **Three Core Process Models
    三种核心过程模型**
    *   **Waterfall Model**: It is plan - driven and sequential, suitable for projects with clear requirements and large - scale engineering projects.
        瀑布模型：它是计划驱动和顺序的，适用于需求明确的大型工程项目。
    *   **Incremental Development**: It involves interleaved activities, which can reduce the cost of changes and facilitate rapid delivery.
        增量开发：它涉及交错的活动，可以降低变更成本并促进快速交付。
    *   **Integration and Configuration**: It is based on software reuse and serves as the standard approach for business systems.
        集成与配置：它基于软件复用，是业务系统的标准方法。
2.  **Coping with Change**: It combines change anticipation (such as prototyping) and change tolerance (such as incremental delivery). Refactoring can prevent the degradation of program structure.
    应对变化：它结合了变化预期（如原型设计）和变化容忍（如增量交付）。重构可以防止程序结构的退化。
3.  **Process Improvement**: There are two approaches, namely the process maturity approach (SEI 5 levels: Initial → Managed → Defined → Quantitatively managed → Optimizing) and the agile approach.
    流程改进：有两种方法，即流程成熟度方法（SEI 5 级：初始 → 受控 → 定义 → 定量管理 → 优化）和敏捷方法。
4.  **Software Prototyping (Key Short - Answer Question)**: It is an initial version used to demonstrate concepts and test design schemes. Its benefits include helping users put forward new requirements, discovering defects in requirements, and verifying the feasibility of designs.
    软件原型（关键简答题）：它是用于展示概念和测试设计方案的一个初始版本。其优点包括帮助用户提出新需求、发现需求中的缺陷，以及验证设计的可行性。

### Key Exam Points
考试重点

*   True/False focus: Development and maintenance are a continuous process, and the waterfall model is not suitable for projects with changing requirements.
    判断题重点：开发和维护是一个持续的过程，瀑布模型不适用于需求变化的项目。
*   Fill - in - the - blank key terms: Ordering (sequence of activities), Debugging (debugging), Change tolerance (change tolerance), Refactoring (refactoring).
    填空题关键词：排序（活动顺序）、调试（调试）、变更容忍度（变更容忍度）、重构（重构）。
*   The concept and benefits of prototyping are the designated short - answer questions, so it is necessary to memorize them in English.
    原型设计的概念和好处是指定的简答题，因此有必要用英语记住它们。

## Chapter 3: Agile Software Development (敏捷软件开发)
第三章：敏捷软件开发

### Core Knowledge
核心知识

1.  **Core Characteristics**: The interleaving of specification, design, and implementation; incremental development; extensive tool support; and minimal documentation.
    核心特征：规范、设计和实现的交错；增量开发；广泛的工具支持；以及极少的文档。
2.  **Agile Manifesto (Key Short - Answer Question)**: The four core values are as follows: Individuals and interactions over processes and tools; Working software over comprehensive documentation; Customer collaboration over contract negotiation; Responding to change over following a plan.
    敏捷宣言（关键简答题）：四个核心价值观如下：个人和互动胜过流程和工具；运行中的软件胜过全面文档；客户合作胜过合同协商；响应变化胜过遵循计划。
3.  **Extreme Programming (XP) Practices**: Refactoring, pair programming, incremental planning, test - first development, and on - site customer.
    极限编程（XP）实践：重构、结对编程、增量规划、测试优先开发和现场客户。
4.  **Scrum Core Terminology**: Product backlog, Sprint, Product Owner (who prioritizes the backlog), and Scrum Master (who coordinates the process).
    Scrum 核心术语：产品待办事项列表、Sprint、产品负责人（负责优先排序待办事项列表）和 Scrum 管理员（负责协调流程）。

### Key Exam Points
关键考试要点

*   Short - answer question: The content of the Agile Manifesto must be written in the original English.
    简答题：敏捷宣言的内容必须用原始英文书写。
*   True/False focus: Refactoring in XP is not only for immediate needs; pair programming encourages refactoring.
    真/假重点：在 XP 中重构不仅仅是为了立即的需求；结对编程鼓励重构。
*   Single - choice focus: Agile methods are not suitable for large - sized products; the responsibility for project delivery lies with the project manager.
    单选题重点：敏捷方法不适用于大型产品；项目交付的责任在于项目经理。

## Chapter 4: Requirements Engineering (需求工程)
第四章：需求工程

### Core Knowledge
核心知识

1.  **Requirements Classification**: User requirements (high - level and abstract) and System requirements (detailed and contractual).
    需求分类：用户需求（高级和抽象的）和系统需求（详细和合同性的）。
2.  **Stakeholders**: Anyone affected by the system, including users, managers, and regulators.
    利益相关者：任何受系统影响的人，包括用户、管理人员和监管者。
3.  **Functional vs. Non - Functional Requirements**: Functional requirements describe what the system does, while non - functional requirements (such as reliability and efficiency) are often more critical.
    功能需求与非功能需求：功能需求描述系统做什么，而非功能需求（如可靠性和效率）通常更为关键。
4.  **Requirements Engineering Process**: Elicitation (interviewing, ethnography) → Specification → Validation (reviews, prototyping, test - case generation).
    需求工程过程：获取（访谈、民族志）→ 规格说明 → 验证（评审、原型设计、测试用例生成）。

### Key Exam Points
考试要点

*   Fill - in - the - blank key terms: Specification (specification), Ethnography (ethnography), Prototyping (prototype).
    填空关键术语：规格说明（specification）、民族志（ethnography）、原型设计（prototype）。
*   Single - choice trap: Non - functional requirements are not less important than functional ones; "easy to use" is an unverifiable non - functional requirement.
    单选题陷阱：非功能性需求并不比功能性需求次要；“易于使用”是一种无法验证的非功能性需求。
*   Connection with Mentcare: It involves requirements such as patient information management and medical staff operation specifications.
    与 Mentcare 的联系：它涉及患者信息管理、医疗人员操作规范等需求。

## Chapter 5: System Modeling (系统建模)
第五章：系统建模 (系统建模)

### Core Knowledge
核心知识

1.  **Four System Perspectives**: External (context model), Interaction (use case/sequence diagram), Structural (class diagram), and Behavioral (activity/state diagram).
    四种系统视角：外部 (上下文模型)、交互 (用例/时序图)、结构 (类图) 和行为 (活动/状态图)。
2.  **UML Core Diagrams**: Activity diagrams, Use case diagrams, Sequence diagrams, Class diagrams, and State diagrams.
    UML 核心图：活动图、用例图、时序图、类图和状态图。
3.  **Key Models**: Context models (defining system boundaries), Class diagrams (association, generalization, aggregation), State diagrams (event - driven state transitions), and MDA (CIM → PIM → PSM).
    关键模型：上下文模型（定义系统边界）、类图（关联、泛化、聚合）、状态图（事件驱动状态转换）和 MDA（CIM→PIM→PSM）。

### Key Exam Points
重点考试内容

*   Fill - in - the - blank focus: Perspective (perspective), Boundaries (boundary), Aggregation (aggregation), PIM (platform - independent model).
    填空题重点：视角（perspective）、边界（boundary）、聚合（aggregation）、PIM（平台无关模型）。
*   Multiple - choice focus: Interaction models include use case diagrams and sequence diagrams; the 1 - to - many relationship in class diagrams (e.g., Patient - Consultation).
    选择题重点：交互模型包括用例图和时序图；类图中的 1 对多关系（例如，Patient-Consultation）。
*   Mentcare - related: Context models of the Mentcare system and interaction models of medical staff operations.
    Mentcare - 相关：Mentcare 系统的上下文模型和医务人员操作交互模型。

## Chapter 6: Architectural Design (体系结构设计)
第 6 章：体系结构设计

### Core Knowledge
核心知识

1.  **Architectural Abstraction**: Architecture in the small (for individual programs) and Architecture in the large (for complex enterprise systems).
    体系结构抽象：小体系结构（针对单个程序）和大体系结构（针对复杂企业系统）。
2.  **Krutchen’s 4 + 1 View Model**: Logical view, Process view, Development view, Physical view, and are linked by use cases/scenarios.
    Krutchen 的 4+1 视图模型：逻辑视图、过程视图、开发视图、物理视图，并通过用例/场景相互关联。
3.  **Five Architectural Patterns
    五种架构模式**
    *   **MVC**: Separates presentation, interaction, and data, suitable for web systems.
        MVC：分离表现、交互和数据，适用于 Web 系统。
    *   **Layered**: Organizes functions into layers, facilitating multi - level security and reuse.
        分层：将功能组织成层次结构，便于多级安全性和重用。
    *   **Client - Server**: Composed of services and clients, suitable for distributed systems.
        客户端-服务器：由服务和客户端组成，适用于分布式系统。
    *   **Pipe and Filter**: For data transformation, suitable for data - processing systems.
        管道和过滤器：用于数据转换，适用于数据处理系统。
    *   **Repository**: Based on a central data repository, suitable for data - intensive systems.
        仓库：基于中央数据仓库，适用于数据密集型系统。

### Key Exam Points
关键考点

*   Single - choice focus: Choosing the appropriate pattern according to scenarios (e.g., separating presentation and data with MVC).
    单选重点：根据场景选择合适的模式（例如，使用 MVC 分离表现层和数据）。
*   True/False focus: The choice of architectural style depends on non - functional requirements; there is no formulaic architectural design process.
    判断重点：架构风格的选择取决于非功能性需求；没有固定的架构设计过程。
*   Fill - in - the - blank key term: Architecture in the large (large - scale architecture).
    填空关键术语：宏观架构（large-scale architecture）。

## Chapter 7: Design and Implementation (设计和实现)
第 7 章：设计和实现

### Core Knowledge
核心知识

1.  **Object - Oriented Design (OOD)**: Objects consist of data and operations; object identification follows the rule that nouns represent objects/attributes and verbs represent operations.
    面向对象设计（OOD）：对象由数据和操作组成；对象识别遵循名词代表对象/属性，动词代表操作的规则。
2.  **Interface Specification**: Interfaces support parallel design, have no attribute section in UML, and there is no 1:1 relationship between objects and interfaces.
    接口规范：接口支持并行设计，UML 中没有属性部分，对象和接口之间没有 1:1 关系。
3.  **Design Patterns (Key Short - Answer Question)**: The four essential elements defined by The Gang of Four are as follows:
    设计模式（关键简答题）：四人帮定义的四个基本要素如下：
    1.  A meaningful name for the pattern.
        一个有意义的模式名称。
    2.  A description of the applicable problem area.
        对适用问题领域的描述。
    3.  A description of the solution (components, relationships, and responsibilities).
        对解决方案的描述（组件、关系和职责）。
    4.  A statement of the consequences (results and trade - offs).
        对后果的陈述（结果和权衡）。
4.  **Implementation Issues**: Host - target development (develop on the host system and run on the target system); tailoring off - the - shelf systems to meet requirements.
    实现问题：主机-目标开发（在主机系统上开发并在目标系统上运行）；定制现成系统以满足需求。

### Key Exam Points
关键考试要点

*   Short - answer question: The four essential elements of design patterns must be memorized in English.
    简答题：设计模式必须记住其四个基本要素（英文）。
*   Fill - in - the - blank focus: Executable (executable), Operations (operations), Target (target), Tailored (tailoring).
    填空题重点：可执行（executable）、操作（operations）、目标（target）、定制（tailoring）。
*   Mentcare - related: Object design of the Mentcare system (e.g., Patient, Consultation classes) and interface design of medical services.
    Mentcare - 相关：Mentcare 系统的对象设计（例如，患者、咨询类）以及医疗服务界面设计。

## Chapter 8: Software Testing (软件测试)
第 8 章：软件测试（软件测试）

### Core Knowledge
核心知识

1.  **Testing Goals**: To verify that the software meets requirements and discover defects; the core principle is that "Testing can only show the presence of errors, not their absence".
    测试目标：验证软件是否满足需求并发现缺陷；核心原则是“测试只能证明错误的存在，不能证明其不存在”。
2.  **Verification & Validation (Key Short - Answer Question)**:
    验证与确认（关键简答题）：
    *   **Verification**: "Are we building the product right?" It checks whether the software meets the stated functional and non - functional requirements.
        验证："我们是否正确地构建了产品？"它检查软件是否满足所声明的功能和非功能要求。
    *   **Validation**: "Are we building the right product?" It ensures that the software meets customer expectations.
        确认："我们是否构建了正确的产品？"它确保软件满足客户期望。
3.  **Development Testing Stages**: Unit testing (testing objects/methods) → Component testing (testing interfaces) → System testing (testing component interactions).
    开发测试阶段：单元测试（测试对象/方法）→ 组件测试（测试接口）→ 系统测试（测试组件交互）。
4.  **Test - Driven Development (TDD)**: It interleaves testing and development; regression testing can prevent new bugs.
    测试驱动开发（TDD）：它将测试和开发交织在一起；回归测试可以防止新出现错误。
5.  **Test Case Design**: Partition testing (testing boundary values and midpoints), black - box testing (without knowing internal logic), and white - box testing (relying on code logic).
    测试用例设计：划分测试（测试边界值和中间值）、黑盒测试（不了解内部逻辑）和白盒测试（依赖代码逻辑）。

### Key Exam Points
关键考试要点

*   Short - answer question: Clearly distinguish the concepts and differences between verification and validation, and express them in English.
    简答题：清晰地区分验证和确认的概念及差异，并用英文表达。
*   Fill - in - the - blank focus: Defects (defect), Confidence (confidence), Release (release), Regression (regression).
    填空题重点：缺陷（defect）、信心（confidence）、发布（release）、回归（regression）。
*   True/False focus: Inspections are static V&V, while testing is dynamic V&V; test cases cannot be automatically designed.
    判断题重点：评审是静态的验证与确认，而测试是动态的验证与确认；测试用例不能自动设计。
