### 一、CSMA/CD 原理与 64 字节的由来（背诵版）
#### 1. CSMA/CD 核心原理（载波监听多路访问/碰撞检测）
以太网共享信道的介质访问控制协议，核心是“先听后发、边发边听、碰撞停发、随机重发”，步骤如下：
- **载波监听**：发送数据前，监听信道是否空闲（无其他信号）；
- **多路访问**：多个站点可同时监听，空闲则竞争发送；
- **碰撞检测**：发送数据时，持续监听信道，若检测到信号冲突（碰撞），立即停止发送；
- **停发重发**：发送“冲突强化信号”（通知所有站点），随后采用“二进制指数退避算法”随机等待一段时间，再次尝试发送。

#### 2. 64 字节的由来（最小帧长的本质）
64 字节是以太网**最小有效 MAC 帧长度**，目的是保证碰撞检测有效，推导逻辑如下：
- 核心要求：**帧的发送时延 ≥ 往返传播时延（2τ）**（确保发送方在碰撞信号传回前仍在发送，能检测到碰撞）；
- 以太网标准规定“争用期 = 512 比特时间”（固定值，覆盖最大网络规模的往返传播时延）；
- 发送速率：早期以太网为 10Mb/s，1 比特时间 = 1/10^7 秒；
- 最小帧长计算：512 比特 = 512 ÷ 8 = 64 字节（含 MAC 头、数据、FCS 校验码，不含物理层前同步码+帧定界符）；
- 结论：若帧长＜64 字节，发送时延＜512 比特时间，发送方可能在碰撞信号传回前已发完帧，无法检测碰撞，因此规定最小帧长为 64 字节（短帧需填充至 64 字节发送）。


### 二、CRC 计算题练习（含详细步骤）
#### 题目：发送数据为 1011001，生成多项式为 G(x) = x⁴ + x³ + 1（对应比特序列 11001），求发送方最终发送的比特序列。
#### 解题步骤（核心：模 2 除法求余数）
1. **确定关键参数**：
   - 生成多项式比特序列：11001（长度 r+1=5，故冗余位长度 r=4）；
   - 原数据：1011001（7 位）。

2. **构造被除数**：
   原数据后补 r 个 0（4 个），得到被除数：10110010000（7+4=11 位）。

3. **模 2 除法（异或运算，无进位/借位）**：
   - 除数：11001（取被除数前 5 位开始运算）；
   - 运算过程：
     ```
     10110010000
     -11001（异或）
     ----------
     01111 01000（余数 4 位时停止，不足补 0 继续除）
     -11001
     ----------
     00110 0000
     -00000
     ----------
     01100
     -11001（补 0 为 01100 → 与 11001 异或）
     ----------
     1001（最终余数，4 位）
     ```

4. **生成发送序列**：
   原数据 + 余数 → 10110011001（7+4=11 位）。

#### 答案：发送方发送的比特序列为 10110011001。


### 三、Hub、Switch、Router 核心区分（表格版）
| 对比维度   | Hub（集线器）              | Switch（交换机）                | Router（路由器）                 |
| ---------- | -------------------------- | ------------------------------- | -------------------------------- |
| 工作层次   | 物理层（1 层）             | 数据链路层（2 层）              | 网络层（3 层）                   |
| 转发依据   | 无转发逻辑，仅放大信号     | MAC 地址（基于 MAC 地址表）     | IP 地址（基于路由表）            |
| 碰撞域隔离 | 不隔离，所有端口同一碰撞域 | 每个端口独立碰撞域              | 每个端口独立碰撞域               |
| 广播域隔离 | 不隔离，所有端口同一广播域 | 不隔离（二层交换机）            | 隔离，每个接口对应一个广播域     |
| 核心特点   | 共享带宽，半双工           | 独享带宽，全双工                | 路由转发，支持异构网络互联       |
| 带宽利用率 | 低（多设备竞争同一带宽）   | 高（端口间并行传输）            | 高（按需路由，隔离广播风暴）     |
| 适用场景   | 早期小型局域网（已淘汰）   | 中小型局域网（接入层/汇聚层）   | 广域网互联、局域网网关（核心层） |
| 额外功能   | 无                         | 自学习、VLAN 划分（三层交换机） | NAT、防火墙、路由选择            |


### 四、碰撞域与广播域的隔离设备总结
#### 1. 核心概念
- **碰撞域**：同一时间段内，只能有一个设备发送数据的网络范围（碰撞会影响域内所有设备）；
- **广播域**：广播包（目的地址为全 1）能到达的网络范围（广播风暴会影响域内所有设备）。

#### 2. 隔离设备对比
| 设备类型             | 碰撞域隔离能力                  | 广播域隔离能力                      |
| -------------------- | ------------------------------- | ----------------------------------- |
| Hub（集线器）        | ×（不隔离，所有端口同一碰撞域） | ×（不隔离，所有端口同一广播域）     |
| Switch（二层交换机） | √（每个端口独立碰撞域）         | ×（不隔离，默认所有端口同一广播域） |
| Router（路由器）     | √（每个接口独立碰撞域）         | √（每个接口独立广播域）             |
| 三层交换机           | √（每个端口独立碰撞域）         | √（基于 VLAN 隔离广播域）           |

#### 关键规律：
- 隔离碰撞域：依赖“二层及以上设备”（Switch、Router），物理层设备（Hub）无此能力；
- 隔离广播域：仅“三层及以上设备”（Router、三层交换机）能实现，二层设备无法隔离广播域。


### 五、交换机自学习原理（三步法）
交换机通过“自学习”动态构建 MAC 地址表（记录 MAC 地址与端口的映射关系），核心步骤如下：
#### 1. 学习阶段（记录 MAC 地址）
- 当交换机收到一个帧时，提取帧的**源 MAC 地址**和**入端口号**；
- 检查 MAC 地址表：若表中无该 MAC 地址，将“源 MAC 地址 + 入端口 + 时间戳”添加到表中；若已存在，更新时间戳（防止地址老化）。

#### 2. 转发阶段（根据目的 MAC 转发）
- 提取帧的**目的 MAC 地址**，查询 MAC 地址表：
  - 表中有对应条目：将帧从对应端口“单播”转发（仅目的端口接收）；
  - 表中无对应条目：将帧从“所有其他端口”（除入端口）“泛洪”（广播转发）；
  - 目的 MAC 为广播地址（FF-FF-FF-FF-FF-FF）：直接泛洪。

#### 3. 老化机制（清理无效条目）
- MAC 地址表条目有“老化时间”（默认一般为 300 秒）；
- 若某条目在老化时间内未被更新（无对应源 MAC 地址的帧传入），交换机自动删除该条目，避免地址表过大。

#### 例子：PC1（MAC-A）通过交换机给 PC2（MAC-B）发数据
1. PC1 发送帧，源 MAC=MAC-A，目的 MAC=MAC-B；
2. 交换机从端口 1 收到帧，学习“MAC-A → 端口 1”，添加到地址表；
3. 查询地址表无 MAC-B，泛洪帧到端口 2、3、4；
4. PC2 从端口 2 接收帧，回复帧的源 MAC=MAC-B，目的 MAC=MAC-A；
5. 交换机从端口 2 收到回复帧，学习“MAC-B → 端口 2”，添加到地址表；
6. 再次查询地址表有 MAC-A → 端口 1，直接单播转发回复帧到端口 1，PC1 接收。
